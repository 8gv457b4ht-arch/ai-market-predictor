# AI Market Predictor

Read-only исследовательская система: публичные рыночные данные Binance / Bybit / OKX → признаки → ансамбль ML → проверка качества данных → журнал прогнозов → оценка результатов → контролируемое самообучение. **Сделки не совершаются, ключи бирж не используются.** Прогнозы — вероятности, а не торговые рекомендации.

## Как это работает (бесплатно, 24/7, без сервера)

| Часть | Где работает | Что делает |
|---|---|---|
| **Backend** (job `backend` в `.github/workflows/main.yml`) | GitHub Actions по расписанию, каждые ~15 мин | Проверка целостности базы (при повреждении — восстановление из последней исправной копии), REST-свечи и тикеры трёх бирж с диагностикой и докачкой пропусков, выборка WebSocket с проверкой меток времени, прогноз, оценка старых прогнозов, обучение (champion/challenger), новости, уведомления; затем поток остаётся открытым до ближайшего закрытия свечи 15m (≤ 16 мин), и прогноз делается через несколько секунд после закрытия; бэкап, экспорт |
| **Состояние** | ветка `data` этого репозитория | SQLite (свечи, ledger, реестр моделей, события), модели, бэкапы, публичный JSON для сайта. Каждый запуск продолжает с того места, где остановился предыдущий |
| **Dashboard** (`web/`, job `pages`) | GitHub Pages | Показывает данные бэкенда; сам браузер дополнительно подключается к WebSocket бирж для живой цены и стакана; тест соединений с вашего устройства |
| **CI** (job `tests`) | GitHub Actions на каждый push | pytest, тесты JS-ядра, браузерный тест, `docker build`, smoke-тест контейнера |

Постоянный режим для собственного сервера: см. раздел «Настоящий 24/7 на сервере» ниже.

Интерфейс: русский (по умолчанию), українська, English — переключатель в верхней панели и в настройках; выбор
сохраняется в браузере, переключение не перезагружает страницу и не сбрасывает модели и журнал.

## Ограничения режима GitHub Actions (честно)
- Запуски по расписанию GitHub выполняет с задержкой (обычно 3–15 мин, иногда больше) и может пропускать при перегрузке. Каждый прогноз хранит `decision_delay_sec`.
- WebSocket не постоянный: он открыт только во время запуска (до ~16 мин). Статусы: **LIVE** — только поток с проверенными метками времени в вашем браузере или постоянный сервер; данные периодического бэкенда не бывают выше **DELAYED**; **STALE** — устарели; **OFFLINE** — источник недоступен; **ERROR** — сбой; **OK** — служба (база, модель, копия) в порядке.
- Свечи, для которых прогноз не был сделан (задержка GitHub), записываются как пропуски и видны в панели модели.
- Серверы GitHub находятся в основном в США: Binance (api.binance.com) и Bybit могут блокировать доступ по региону. Бэкенд пробует запасные хосты (`data-api.binance.vision`, `api.bytick.com`, `aws.okx.com`), выбирает доступную биржу автоматически и показывает причину отказа.
- В публичном репозитории GitHub отключает расписание после 60 дней без активности репозитория. Если это случится, нажмите «Enable workflow» во вкладке Actions.

## Уведомления 24/7 (по желанию)
Settings → Secrets and variables → Actions → New repository secret:
- `NTFY_TOPIC` — длинное случайное имя; установите приложение **ntfy** и подпишитесь на этот топик (аккаунт не нужен);
- или `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`;
- по желанию `ANTHROPIC_API_KEY` — анализ новостей через Claude (без него работает прозрачный анализ по правилам).

Секреты никогда не попадают в код, ветку `data` или на сайт (это проверяет тест).

## Прогнозы на будущее по 14 горизонтам (5 с … 1 сутки)
- Прогноз делается **заранее**: в момент `created` только по данным с метками времени не позже него (`data_ts ≤ created`),
  цель — цена через горизонт (`target = created + горизонт`). Горизонт и частота пересчёта разделены
  (например, прогноз на 15 минут пересчитывается каждые 150 с; на сервере — чаще).
- Содержимое: биржа и инструмент, текущая цена, вероятности роста/падения/боковика (рост и падение = движение больше
  издержек на круг), ожидаемый диапазон 10–90 % и медиана, неопределённость, время проверки, причина,
  решение LONG / SHORT / NO TRADE (аналитический режим, ордеров нет), базовый прогноз для сравнения, версия модели,
  снимок входных данных и его хэш (`Forecaster.reproduce` пересчитывает прогноз из снимка).
- Журнал `forecasts` только дописывается: триггер базы запрещает менять прогноз, исход записывается один раз.
  Исход — последняя сделка не позже цели (1-секундные бары потока сделок) или, для горизонтов от 15 минут,
  закрытие минутной свечи не раньше чем за 60 с до цели; иначе исход отмечается как отсутствующий, не угадывается.
- Модели учатся на реально существующих рядах: секунды — на 1-секундных барах потока (накапливаются по ходу работы),
  минуты — на минутных свечах (30 дней), часы — на 15m и 1h. Первая модель проверяется на последних 30 % данных,
  каждая следующая — только на свежем окне, которое ещё не использовалось; переход — лишь при подтверждённом улучшении.
  Статусы: сбор данных → проверена (лучше базовой) / не лучше базовой → ухудшилась (повторная проверка).
  Время обучения распределяется по приоритету (лучшие и ухудшившиеся — чаще), критерии оценки при этом не меняются.
- Причины NO TRADE: DATA STALE, MODEL NOT VALIDATED, MODEL NOT BETTER THAN BASELINE, NO EDGE AFTER COSTS,
  LOW CONFIDENCE, INSUFFICIENT DATA. Измеренная диагностика: `python scripts/forecast_diagnostics.py --db …`.
- В режиме GitHub Actions прогнозы делаются во время запусков (поток открыт до ~16 мин), реже (×4) и с меньшим
  хранением; полноценная работа секундных горизонтов — на постоянном сервере.

## Управление без сервера: файлы `control/`
Секретов здесь нет; токены — только в Secrets.
- `control/notify.json` — минимальные условия уведомлений: `{"enabled": true, "events": ["signals","outages","promotions"], "min_confidence": 0.6, "min_quality": 0.8, "timeframes": ["15m"], "symbols": ["BTC/USDT"], "max_age_sec": 600, "language": "ru"}`. Устаревший сигнал (старше `max_age_sec` после закрытия свечи) не отправляется; одна свеча никогда не отправляется дважды.
- `control/commands.json` — разовые команды (каждый `id` выполняется один раз):
  `{"commands": [{"id": "rollback-1", "action": "rollback", "model_key": "BTC/USDT|15m|h4"}]}` — вернуть предыдущую модель;
  `{"id": "restore-1", "action": "restore_backup"}` — восстановить базу из последней исправной копии; `{"id": "b1", "action": "backup"}`.
Примеры: `control/*.example.json`. Изменить файл можно прямо на сайте GitHub (карандаш → Commit).

## Почему NO TRADE
Причина показывается кодом и объяснением на выбранном языке: **LOW CONFIDENCE**, **STALE DATA**, **INSUFFICIENT HISTORY**, **MODEL NOT READY**, **HIGH SPREAD**, **MODEL NOT BETTER THAN BASELINE** (вне выборки модель не лучше базовых частот с вероятностью ≥ 95 %), **NO EDGE AFTER COSTS** (собственные сигналы модели вне выборки — не меньше 30 — не дали плюса после издержек), а также DATA QUALITY, ABNORMAL MARKET, NEWS CONFLICT. Направление и выгодность разделены: вероятность роста сама по себе не означает выгодную сделку. Порог **никогда не снижается автоматически**.

Для каждого прогноза (клик по строке журнала): вероятности, порог, режим, качество и свежесть данных, версия модели, главные факторы, ожидаемые издержки, результат сигналов модели после издержек, сравнение с базовым прогнозом, время проверки и фактический результат. Журнал фильтруется по активу, таймфрейму, модели и периоду. Отчёт об изменениях модели показывает метрики до/после и по режимам рынка.

Исследование на реальных данных: `docs/RESEARCH_2026-10-09.md`; аудит: `docs/AUDIT_2026-10-09.md`; протокол проверок: `TEST_RESULTS.md`.

## Настоящий 24/7 на сервере (подготовлено, на реальном сервере не проверено)
**Пошаговая инструкция для Oracle Cloud Free (бесплатно): [`deploy/oracle/README.md`](deploy/oracle/README.md)** —
установка одной командой `sudo bash install.sh`.

GitHub Actions — периодический запуск, а не постоянный процесс. Для круглосуточного сбора нужен сервер (VPS 1 vCPU / 1–2 GB, Docker) **в регионе, где Binance и Bybit не блокируют доступ** (например, ЕС или Азия):
1. `git clone` репозитория на сервер, `cp .env.example .env`, в `.env`: `BACKEND_MODE=continuous`, `PRIMARY_EXCHANGE=auto`, `PUBLISH_REPO=<владелец>/<репозиторий>`, `PUBLISH_TOKEN=<fine-grained token, только этот репозиторий, Contents: read and write>`, при желании `NTFY_TOPIC` / Telegram.
2. `docker compose up -d --build` — службы collector (постоянный WebSocket с переподключением), predictor (прогноз через секунды после закрытия свечи), learner, news, backup, publisher (каждые 2 мин публикует данные сайта в ветку `data`, раз в час — снимок базы и модели); `restart: unless-stopped` + healthcheck каждой службы.
3. В репозитории: Settings → Secrets and variables → Actions → **Variables** → `BACKEND_MODE` = `external` — расписание GitHub перестаёт писать в ту же ветку. Сайт остаётся тем же и показывает LIVE, когда данные сервера свежие.
4. Проверка: `scripts/status.sh`, `docker compose ps`, панель состояния на сайте.

Проверка без сервера: Actions → AI Market Predictor → Run workflow → `soak` — несколько часов работы постоянных компонентов на реальных данных (результаты в аннотациях запуска; ветка `data` не меняется). Это проверяет часы, а не круглосуточную работу.

## Как обновить код без git
Загрузите новый `ai-market-predictor-repo.zip` через **Add file → Upload files** в корень репозитория. Workflow сам распакует его, прогонит тесты, опубликует сайт и запустит бэкенд.

